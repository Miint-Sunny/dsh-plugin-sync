# @miint-sunny/dsh-plugin-sync

[English](README.en.md)

DeepSeek Harness（DSH）桌面端插件，用来在两台 Mac 之间同步桌面端插件。只支持 macOS。同步的内容是：

- 安装了哪些插件，各自的版本；
- 插件的启用状态，包括官方插件；
- 插件里各个组件的开关；
- 兼容性豁免。

两台都装上这个插件，在一台导出，在另一台导入。

它不同步：会话、登录状态、`.credentials.yaml`、插件的配置内容（里面可能有密钥）、MCP、skill、`dsh-tui` profile，以及 App 本身。

## 需要什么

- 两台 Mac，都装上本插件。只支持 macOS；Windows 还不支持。
- DeepSeek Harness 桌面端：`>=0.2.1-rc.5 <0.3.0-0`（见 `package.json` 的 `engines.dsh`，范围外版本不加载）；已在 App 0.2.2-rc.5 上验证。
- 用 Git 仓库同步时需要系统自带的 git，和一个你有读写权限的远程仓库（或本机路径）。

## 安装

包名是 `@miint-sunny/dsh-plugin-sync`，目前尚未发布到 npm。

1. 到 [GitHub Releases](https://github.com/Miint-Sunny/dsh-plugin-sync/releases) 下载 `.tgz` 安装包，保存到本机。
2. 在 DSH 的「插件」页点「添加」，填写 `.tgz` 文件的绝对路径，例如 `/path/to/miint-sunny-dsh-plugin-sync-0.4.0.tgz`，然后安装。示例路径需要换成实际路径。
3. 安装完成后重启 App，在插件页确认本插件的组件行已挂载并运行。

npm 发布后，可在同一个输入框填写完整包名 `@miint-sunny/dsh-plugin-sync` 安装。

也可以完全退出 App 后，使用 App 自带的 CLI 安装本地包：

```sh
"/Applications/DeepSeek Harness.app/Contents/Resources/runtime/cli/bin/dsh" plugin --profile desktop add /path/to/miint-sunny-dsh-plugin-sync-0.4.0.tgz
```

本插件固定管理同一 `DSH_HOME` 下的 `desktop` profile，不支持将命令中的名称替换成其他 profile 作为同步目标。首次使用命令行安装前，先打开 DSH 桌面端一次，让 App 初始化 `desktop`，再完全退出；命令行不会代替 App 创建它。安装后重新打开 App。

## 更新与卸载

- 通过 npm 包名安装：发布新版后，在插件页使用「更新」，完成后重启 App。
- 通过本地 `.tgz` 安装：插件页没有按 npm 检查更新的入口。先卸载当前包，再用新版 `.tgz` 的绝对路径重新安装，完成后重启 App。
- 卸载：在插件页打开本插件，点「卸载」。暂时不用时可选择「停用」。

## 旧包迁移

如果已经安装无作用域的 `dsh-plugin-sync`，先在插件页卸载旧包，再按上面的步骤安装 `@miint-sunny/dsh-plugin-sync`。不要同时安装两个名称。只更新包名，保留已有配置和数据。

## 用法

在 DSH 的插件页打开 `dsh-plugin-sync`，页面上有「导入」「导出」「设置」三个选项卡。插件列表和 DSH 插件页一样显示图标、名称和说明，按「第三方插件」「官方插件」分组。

### 导入

1. **来源**：选「压缩包」或「Git 仓库」。
   - 压缩包：「选择文件…」，选另一台导出的 .zip，选好后自动比较。
   - Git 仓库：列出仓库里的机器，默认选最近导出的那台，选中后自动比较。页面只读本地副本，不联网；要取远程的新提交，点「拉取」。本机那一行标着「本机」，不能选。
2. **快照**：显示来源机器、导出时间和 DSH 版本。来源的 DSH 比本机新时不能导入，要先升级本机 App；本机较新时会提示快照中的兼容性豁免不适用于本机。
3. **变更**：一个插件一行，用标签标出变更类型：安装、升级、降级、卸载、启用、停用、组件、兼容性豁免。
   - 同一个插件的几项变更共用一个勾选框，一起应用或一起跳过。
   - 默认勾选。降级和兼容性豁免默认不勾。勾选不会保存，每次比较重新给默认值。
   - 只有同时满足三个条件的插件才会出现在「卸载」里：
     1. 上次从同一台机器导入时有它；
     2. 这次快照里没有；
     3. 来源机器也没有把它列为不导出。

     本机自己装的插件不会被卸载。
   - 会新允许运行安装脚本的依赖（`allowBuilds`），写在对应插件那一行。
   - 不变更的插件折叠在最后，按原因列出：与快照相同、仅本机安装、来源机器未导出。
4. **应用**：点「应用 N 项变更」，确认框里写明 App 会退出、正在进行的对话和任务会中断，并列出降级、兼容性豁免和新放行的安装脚本。勾上「我已了解风险，并愿意继续」，点「退出并应用」：
   1. App 退出；
   2. 备份 profile，写入文件，安装并校验；
   3. App 重新打开。

   App 重新打开后，结果显示在选项卡上方，可以展开每一步和备份、日志的位置，点「关闭」后不再显示。

### 导出

1. **导出位置**：选「压缩包」或「Git 仓库」，上次的选择会记住。
   - 压缩包：生成 .zip，包含 `snapshot.json` 和本地插件的包。点「下载」保存，传到另一台（比如用 AirDrop）。下载链接在 App 重启后失效，到时重新导出即可。
   - Git 仓库：提交到 `machines/<机器 ID>/` 并推送，一步完成。推送失败时提交保留在本地副本里，页面上可以「重试推送」。插件不会新建仓库、不会添加远程，也不会强制推送。远程地址是本机路径时只提交，不推送。
2. **插件**：本机的第三方插件和官方插件，每行一个勾选框，取消勾选的插件不导出，整行变灰。勾选会立即保存。新装的插件默认导出。
   - 第三方插件导出版本、来源、启用状态、组件开关和兼容性豁免。
   - 官方插件导出启用状态和组件开关。始终启用的基础组合包不列。
   - 快照会记下哪些插件没导出。导入方据此区分「来源机器卸载了」和「来源机器没导出」。

本地插件有两种：

- 以 `link:` 装的本地仓库：要求工作区没有未提交的更改，插件记下提交号，用 App 自带的 pnpm 打包。有未提交的更改时，列表里那一行会提前标出来。
- `local-plugins/` 下的本地包：原样带走。

导出前会做密钥扫描：

- 先从本机 profile 补丁里收集像密钥的值；
- 再扫快照里的每个文件，tgz 会先解压再扫；
- 同时检查常见的令牌和私钥格式。

命中就停止导出，只报文件名和命中数，不显示内容。这只是额外一道防线，不能代替人工检查。

### 设置

改完点「保存」。

- **本机名称**：显示在快照和 Git 仓库的机器列表中，留空时使用 macOS 的电脑名称。
- **机器 ID**：Git 仓库里的目录名，由主机名生成，改名称不影响它。
- **远程地址**：支持 https、ssh（包括 `git@主机:路径`）地址和本机绝对路径。读写使用系统 git 的凭据，插件不读取、不保存令牌。地址不能包含密码，https 地址也不能带用户名；不接受 `http:` 和 `git:`。「测试连接」用 `git ls-remote` 检查能否访问。
- **数据位置**：数据目录、备份目录，以及导出文件保留几次（最近 5 次）。

## 安全

- **接口访问**：所有接口都要求本机回环地址和回环 Host。带 Origin 的请求必须同源。还要通过官方 `connection.requestRejection(req)` 的登录校验，拿不到官方 connection 时一律拒绝。请求体有大小上限。
- **不导出的插件**：快照里不出现它的包、bundle、组件开关、兼容性豁免、补丁或锁文件条目。
- **组件归属**：组件开关属于哪个插件，按官方 `pluginManager.listBundles()` 里各组合包声明的组件判断。找不到归属的组件开关不导出，导入时也不写。
- **组件开关的写法**：
  - profile 补丁里已有这一行，就只改 `disabled`，其它字节不动。
  - 没有这一行（插件自带、本机从没切换过），就在文件末尾追加 `{id, disabled}`，和官方开关的写法一样。
  - 改完的文本必须解析成预期的变化才会写入。
- **未选中的插件不变**：
  - 导入只合并选中插件依赖树里的补丁、`allowBuilds` 和 `overrides`。
  - 应用计划会列出不变更的插件。应用进程在退出 App 之前核对两件事：
    - 这些插件的依赖和 bundle 都不变；
    - 计划里的组件开关、兼容性豁免和快照补丁都不属于它们。
- **补丁**：这次没动的插件保留本机的补丁；装或改的插件用快照里的补丁。
- **应用过程**：
  - 同一时间只能有一个导入进程，靠应用锁保证。
  - 先备份 profile 文件，旧的 `node_modules` 改名放进备份。
  - 失败时直接恢复，不联网重装。
  - 记下「已应用的快照」之后，后续的收尾步骤失败只记警告，不回滚。
  - 备份在 `~/.dsh/backups/plugin-sync/`。
  - 不再需要的文件挪进 `~/.Trash/dsh-plugin-sync-<日期>/`。
- **兼容性豁免**：只在快照和本机是同一个确切 DSH 版本时提供，选了必须确认风险。

## 已知限制

- 导入会退出并重新打开 App，正在进行的对话和任务会中断。
- 来源机器的 DSH 比本机新时不能导入，要先升级本机 App。
- 兼容性豁免只在快照和本机是同一个确切 DSH 版本时提供。
- 不同步的内容见开头；本机自己装的插件不会因导入被卸载。

## 遇到问题

在 [GitHub Issues](https://github.com/Miint-Sunny/dsh-plugin-sync/issues) 提交问题报告。熟人试用时，也可以直接联系提供插件的人。

请提供 DSH App 版本、插件名和版本、macOS 版本和芯片、操作步骤、实际结果和预期结果，以及插件页里未挂载或未运行的组件行与报错原文；截图也可以。请先删除 API 密钥、令牌、完整配置文件和私人聊天。

## 开发

从 git 克隆以后先 `pnpm install` 再 `pnpm test`，测试要用本机的 DSH App（装在别处时用 `DSH_APP` 指定 `.app` 的路径）。导出检查 `pnpm run public:check` 只认 git 跟踪的文件，在 GitHub 自动附的源码压缩包里跑不了。
